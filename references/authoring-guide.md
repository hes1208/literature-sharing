# 写作与证据处理 Writing and evidence

## 学习案例 Learn from paired examples

先按标题、DOI或目录关系匹配原文与分享稿。不要仅学习 Word 的表面格式；比较同一内容在原文和分享稿中的表达，判断作者保留了哪些背景转折、方法细节、定量发现和解释逻辑。

记录简短的任务内样式笔记：章节是否合并、段落长短、图表插入位置、符号说明方式、讨论压缩程度。样式笔记留在任务工作目录，不写入最终分享正文。不要复制案例中与分享无关的公众号页脚、留言区、宣传内容。

案例之间可能彼此矛盾（有的案例把表译成中文，有的直接截图）。以本文件的硬性规则为准，不以“某个案例这样写过”为由改变规则。

Match examples by title/DOI, compare source evidence with the summary, and learn selection and organization rather than copying facts or unrelated page furniture.

## 标题忠实原文 Headings follow the source

分享稿的章节标题分两类，规则不同：

| 层级 | 规则 |
| --- | --- |
| 八个主章节（文章信息 / 摘要 / 背景 / 方法 / 结果 / 讨论 / 结论 / 英文摘要） | 使用本 skill 的固定命名，可中译。 |
| 结果与讨论的子标题 | **必须与原文逐条对应**：数量相同、顺序相同、含义相同，只允许译为中文。 |
| 方法的子标题 | 允许功能性切分（数据来源、测度、计量策略），但原文有明确小节名时优先沿用。 |

具体做法：

1. 读原文时先抄下 `Results` / `Discussion` 下的全部子标题原句（含层级），逐条译成中文，形成对照表，直接作为分享稿子标题。
2. 原文结果部分只有一个 `Results` 而没有子标题时，分享稿也不加子标题，用段首主题句＋图表引用串联。
3. 不得把原文三个子标题合并成两个，也不得为了“看起来更完整”新增引言式小节（例如自行加一节“数据集覆盖结构”，而原文并无此标题）。
4. 子标题里不要塞结论或数值；保持与原文同等的抽象层级。
5. 若原文子标题本身含糊，直译后可加一个极短括注说明它讲什么，但不改标题主干。

反例（真实返工原因）：原文结果为 `Technology characteristics` / `Country characteristics` / `Combined effects` 三节，分享稿却写成“5.1 数据集的覆盖结构 / 5.2 技术特征与扩散速度 / 5.3 国家特征与扩散速度 / 5.4 技术特征与国家特征的联合效应”——多出一节且措辞被改写。正确做法是保留三节，把“数据覆盖”并入引言式段落。

Subsection headings under Results and Discussion must mirror the source one-to-one — same count, same order, same meaning, translated only. Never invent, merge, split or re-theme them.

## 内容取舍 Editorial decisions

| 部分 / Section | 保留 / Keep | 避免 / Avoid | 正文预算 |
| --- | --- | --- | --- |
| 背景 Background | 关键矛盾、知识缺口、研究必要性 | 按引言逐段翻译 | 300–450 字 |
| 方法 Methods | 数据和筛选、核心逻辑、公式与符号、识别或情景假设 | 只列方法名称，或照搬软件参数而不解释用途 | 600–900 字 |
| 结果 Results | 每张图表支撑的核心发现和比较条件 | 全文结果翻译、无图表引用的笼统总结 | 800–1200 字 |
| 讨论 Discussion | 解释链、证据边界、意义、作者的局限判断 | 将假说当已验证机制 | 350–550 字 |
| 政策 Policy | 原文支持的行动逻辑与适用对象 | 把研究者推测扩写为普遍政策结论 | 250–400 字 |

摘要译文、图表题注与注释、公式符号解释不计入预算，任何情况下不得为压字数而删减。

## 压缩手法 Compression tactics

面向公众号推送时，可读性来自“短句 + 数字 + 图表”，而不是覆盖全部细节。按下列顺序压缩：

1. **删铺垫**：去掉“值得注意”“大量研究表明”“已有丰富文献讨论了”等过渡套话，直接进入判断。
2. **并同向证据**：同一结论的多组稳健性检验合并为一句，只留最强的一组。
3. **只报三元组**：方向 + 量级 + 比较基准。例如“晚 10 年商业化，预测扩散速度高 0.02”，而不是复述回归设定。
4. **细节下沉**：口径、单位换算、异方差处理、补充材料编号移入图注或括号。
5. **背景四步法**：为何重要 → 已知什么 → 缺什么 → 本文做什么，每步 1–2 句，不多于 5 段。
6. **结果按图组织**：一段对应一张图或一组子图，先给结论句，再给 1–2 个数值。

压缩的边界：不得删掉任何进入覆盖范围的图表引用、不得删掉原文明确给出的不确定性（P 值、置信区间、样本量）、不得把“未检验”写成“已证明”。

## 证据台账 Evidence ledger

任务内建立 JSON 或等价表格，至少包含：

- 文献标题、摘要原文及其定位。
- 所有主文图、表、公式的编号、PDF页码、裁剪区域、截图文件。
- 每张图表对应结果段落、主要数值、比较对象及子图引用。
- 原文结果/讨论子标题原句及其对应中译（用于核对标题忠实性）。
- 题注/注释翻译状态、所有公式符号解释状态。
- 存在冲突的原文位置与处理方式。

可参考 [evidence-ledger.example.json](../examples/evidence-ledger.example.json)。例子使用模拟条目；实际条目须来自当前论文，不能复制模拟数量或坐标。`check_share.py` 的 `caption` 与 `citation` 是对成稿中实际文本的精确字符串匹配，且必须在不同段落，不能用题注本身冒充结果引用。

Maintain the ledger locally. Record every in-scope object, source location, screenshot, narrative citation, caption translation, source subheading and symbol review. Do not publish ledgers containing private paper paths by default.

## 图表与公式 Screenshots

1. 先查看完整 PDF 页面，辨认图、表、公式及题注边界；不要只用自动检测到的图片对象，因为许多图表是矢量或跨对象组成的。
2. 坐标以**渲染后页面左上角**为原点，单位为 PDF point（1/72英寸），矩形为 `[left, top, right, bottom]`。旋转页面以渲染显示后的方向为准。
3. 先渲染整页，再制定裁剪方案；`pdf_assets.py` 的页面索引从1开始，默认300 DPI。
4. 图表内容须完整，原英文题注可截去并在 Word 中用完整中文译文替代；图内图例和轴标签属于图表内容，不可误裁。裁切时留意原文版面在图表上下各有一条细分隔线，向内收 3–5 pt 即可去掉，避免成稿出现多余横线。
5. 长表可按行拆分，重复表头；大图可按有意义的子图拆分，并保留所有图例和说明。结果引用仍用原编号。
6. 截取公式本身和原编号；公式说明作为可编辑文字。若原符号写法疑似错误，保留截图并校注，勿悄悄重画成“正确公式”。
7. 整页渲染分辨率建议 300–400 DPI；窄幅公式按原生尺寸的 1.2–1.4 倍排版即可与正文 10.5 pt 视觉匹配，不必强行放满整行。

### 表格：只截图 Table screenshots only

- 表格与图采用同一处理：**截图 + 中文表名（上）+ 中文注释（下）**。
- 表体保持原文语言，**不重制为 Word 原生表格、不翻译表头与单元格**。重建会带来三类风险：数值抄录错误、合并单元格结构失真、读者无法逐格对照原文。
- 中文表名与中文注释中应交代表内缩写、样本口径与“资料来源：原文 Table N”。
- 跨页长表：分两段截图，第二段重复表头并标“续表 N”；不使用“缩小到一页”的做法。
- 唯一例外：原文表格仅存在于无法截图的补充材料（如加密附件、纯文本表格）时，可重建为 Word 表格，但必须在注释中写明“本表据补充材料 Table Sx 重排，原文表体为英文”，并保留原英文列名。

Use whole-page rendering before cropping; vector graphics and legends may not be standalone images. Inspect the actual crops, not just the crop coordinates. Tables are screenshots too — never rebuilt, never translated inside.

## 数字与统计 Numerical interpretation

- 同时核对摘要、正文、图注和表格。数据不一致时记录具体位置，不自行拼出一个“统一样本量”。
- P值应在0—1之间；负的“P值”可能是误标的系数，必须核对，不能据此报告显著性。
- 箱线图、中位数、均值、置信区间、标准差和标准误各不相同，按原文定义翻译。
- 报告变化时交代基准年/情景、单位、地区与样本。百分比变化和百分点变化区别处理。
- log变量明确原指标及对数口径；不能未经换算把对数系数当作百分比。
- 关联、模型预测和因果识别分开。控制变量引入后关系反转时，正文应保留这一条件。
- 原文若称参数无量纲，可忠实报告其用语并解释应用语境；不要把逻辑斯蒂陡峭度直接等同于实际年增长百分比。

## Word 排版与交付 Layout

优先遵循用户提供的参考版式。没有指定时采用清晰标题层级、易读中文正文字体、A4或适合图表的页面；用留白与字重形成层级，不加无必要的封面、装饰线或空白页。

图片按原比例缩放。题名与图表成组，中文图注与图保持邻近。需要分页时使用段落分页属性并检查实际效果，避免分页符段落被挤到新页形成空页。图片撑满页时可以将前导文字调整到相邻页，不缩小到难以辨认。

排版常见缺陷（实测）：

- 图与其注释被分页切开 → 给图片段落与题注段落设“与下段同页”。
- 表格首行落在页底、其余在次页 → 除末行外全表设“与下段同页”；跨页长表则设表头重复＋行内禁止断页。
- 标题落在页底 → 各级标题“与下段同页”。
- 表格列宽总和大于正文宽度 → 采用固定布局并显式指定每列宽度，单元格边距收窄到 0.1 cm。

优先使用环境已有的文档生成和渲染工具。可用工具或宿主另有文档技能时遵循其适用规范；本仓库不依赖特定 MCP、付费服务或某个开发者的运行时路径。渲染必须覆盖最终版本全部页面。

Prefer the user's reference styling. Use an available DOCX engine and renderer; this repository does not bundle a renderer. Never equate successful text extraction or a script pass with successful page inspection.
